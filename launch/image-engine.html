ChatGPT images in bulk

Three ways to stop generating one at a time, all of them running on the ChatGPT account we already pay for. One works this afternoon with no code. One is a real batch tool that already exists. One is the multi-account build — your idea, and the right end state.

Built — VegToon Image Batch v1.4.1 · ready

One file. Double-click it, sign in once, paste prompts one per line, pick a folder, press Generate. Images come from ChatGPT and count against your ChatGPT plan — no API key, no API bill.

⬇ Download VegToon-Image-Batch.py Python (one-time install)
  1. Install Python once — python.org, run the installer, and tick "Add Python to PATH" on the first screen. That is the only thing you ever install by hand.
  2. Double-click VegToon-Image-Batch.py. A black window opens and your browser opens the app. Keep the black window open while you work; closing it quits the app.
  3. Press "Sign in with ChatGPT". Your browser opens the normal ChatGPT sign-in page and comes straight back — nothing to download. If your browser doesn't open by itself, the page shows a blue sign-in link to click instead. The app never sees your password.
  4. Paste prompts, one per line (or separate longer ones with a line containing only ---), choose the output folder, press Generate. You get a live list showing each image as it saves.
Try the test run first. There's a "Test run" tick-box next to Generate. It writes placeholder images without touching ChatGPT — so you can confirm the app runs on your PC and files land in the right folder before spending a single image from your quota. If the test run works and the real run doesn't, the problem is sign-in, not the app.

What's in it

Shape, quality, count

Portrait 2:3 for 9:16 shorts, quality set to high on every image, and 1–8 images per prompt. The web app never lets you fix these.

Never overwrites

Files are named prefix-001.png upward. If a name already exists it adds a number instead of destroying the old one.

Handles the limit

If ChatGPT rate-limits mid-batch, it reads how long to wait, waits, and retries up to 4 times — showing you the countdown instead of just failing. And if the connection drops mid-image, it quietly retries that prompt twice before giving up.

Tested before it reached you: 24 automated checks on the engine (batch queue, file writing, no-overwrite, bad-folder handling, settings) and 24 more driving the real page in a browser (buttons, guards, progress, layout at phone/laptop/desktop widths, zero console errors) — plus the automatic Codex download run for real on both the Windows and Linux packages.

It updates itself. When I ship a fix, the app shows a "Version X is ready" bar with an Update now button — one click, no re-download by hand. There is also a Send a report to Claude button that ships the version numbers, each prompt's status and error, and the console lines to me, so I can diagnose that PC without touching it. It never sends your password, your sign-in token or your files, and there is a tick-box to switch it off.

What it's built on

★ ChatGPT's own image tool, via the Codex sign-in

The app posts to chatgpt.com/backend-api/codex/responses with ChatGPT's hosted image tool, using the token that the official codex login writes. Two reasons this is the right pipe: it's billed to your subscription rather than an API account, and it is not the chat endpoint — so it never touches the Cloudflare wall that killed every older ChatGPT automation project. The protocol is copied from jdmnk/codex-imagegen-cli (Apache-2.0), which is the reference implementation for this route.

Path 1 — the extension today, no code

You asked for "an extension that keeps submitting prompts". Two exist, both current, both image-aware — they paste your prompt list into chatgpt.com one at a time, wait for each image to finish rendering, and auto-download it. Nothing to install beyond the browser.

ExtensionUsersUpdatedWhat it does
ChatGPT Automation — Auto ChatGPT~10,00026 Jul 2026Text-to-image and image-to-image, aspect-ratio control (16:9 / 9:16 / 1:1), auto-download. The most image-specific of the two.
ChatGPT Image Auto~100,00029 Apr 2026Reads the finished image straight out of the page payload rather than guessing from the DOM, so it doesn't fire the next prompt early. Bigger userbase, slightly older.
Try this first, tonight. It costs nothing and it tells us the one thing no amount of research can: how many images your account actually gives us before it stops. That number decides whether Path 2 is enough or whether we need Path 3. Run one short's worth of prompts — 8 images — and tell me where it stopped.
Don't bother with Superpower ChatGPT (the big 100k-user one you may already know). Its queue only waits for the send button to come back, so with image prompts it fires the next one while the picture is still rendering. Wrong tool for this.

Path 2 — Codex batch CLI the real one

This is the proper answer to "can Codex generate too?". Codex has built-in image generation — OpenAI's own docs say it "uses gpt-image-2 and counts toward your general Codex usage limits", i.e. it comes out of the Plus subscription, not an API bill. codex-imagegen-cli wraps that in a batch command.

Why this beats the extension: it's a file in, a folder of PNGs out. No browser open, no tab to babysit, and it plugs straight into how we already work — our script pages emit a batch copy-block of image prompts, and that block becomes the input file almost unchanged.

  1. Install Codex and log in once. Browser opens, you sign in with the ChatGPT account, done. No API key anywhere.
  2. Install the batch tool (one clone + one command).
  3. Write the prompt file — one line per image, JSON. I'll generate this straight from the short's prompt block so you never hand-write it.
  4. Run the batch and collect the folder.
Setup — run once
npm install -g @openai/codex
codex login          # pick the "Sign in with ChatGPT" option

git clone https://github.com/jdmnk/codex-imagegen-cli.git
cd codex-imagegen-cli
uv sync --dev
uv tool install -e .

codex-imagegen --help
jobs.jsonl — one line per image (portrait stills for a 9:16 short)
{"prompt":"A photoreal ultra-detailed 3D render of an anthropomorphic potato villager standing in a mud-walled village courtyard at mid-morning. Locked-off tripod camera, no on-screen text of any kind.","out":"16-1.png"}
{"prompt":"A photoreal ultra-detailed 3D render of an anthropomorphic tomato shopkeeper leaning on a glass counter inside a small village shop. Run it
codex-imagegen batch \
  --input jobs.jsonl \
  --out-dir out/ \
  --size 1024x1536 \
  --quality high

What it gives us that the web app doesn't

Portrait natively

--size 1024x1536 — proper 2:3 stills for a 9:16 short, set per run instead of asked for in prose every time.

Quality as a flag

--quality high on every image, not left to chance. The web app never exposes this.

The cast lock

The third line of the example is the important one: edit mode takes up to five input images. Feed it our five approved portraits and every render is conditioned on the real cast instead of a text description of them.

The honest catch, from OpenAI's own page: image turns burn your included allowance 3–5× faster than normal Codex use, and edit jobs have a per-minute limit on input images (the tool retries with backoff). It is subscription-gated to Plus and above. And it is not an officially supported automation surface — Codex's internals can change and break the tool.

Path 3 — ChatGPT Flow Multi the build

Your third idea: "if there's a provision of making something like veo3 multi, we can embed chatgpt there and it can generate images for us in bulk." Yes — and it's a closer fit than it was for Flow, because the hard part of Path 2 is already solved and proven by a working repo.

How it works

PieceWhere it comes from
One isolated browser session per ChatGPT account, manual login onceExactly the pattern the Flow tool uses — a separate persisted partition per account. Never scripts the sign-in screen.
Harvest each account's Codex login tokenSame file shape codex-imagegen-cli already reads. The batch tool even accepts --auth-file, so each account is just a different file path.
Round-robin the prompt queue across accounts; drop an account when it hits its limit and carry onThe Flow tool already does precisely this for exhausted credits. Same logic, different exhaustion signal.
Talk to ChatGPT's image endpoint directlychatgpt.com/backend-api/codex/responses — not the chat endpoint. This matters: the chat endpoint is behind the Cloudflare proof-of-work wall that killed every old ChatGPT automation project. This one isn't.

N accounts = N× the daily images. That is the entire point, and it's the same reason we pooled accounts for Veo.

How I'd build it this time, given the Flow tool didn't work out. Command line first, Electron never — or at least not until the engine is proven. Path 2's CLI already works standalone; step one is a thin script that runs it across N auth files and reports what each account did. If that runs clean for a week of real shorts, then it's worth a window and buttons. The Flow tool's problem was that a lot of UI got built on top of an engine that was still fighting Google. I'm not repeating that shape.

The one thing that decides everything

All three paths run into the same wall: how many images a single Plus account gives per day. OpenAI publishes no number — I checked every help article, and every figure circulating online traces back to content farms rather than to OpenAI. What's consistently reported is a few dozen images, then a cooldown measured in hours, and refused generations still count against you.

So we measure it instead of researching it. Path 1 tonight, 8 prompts, tell me where it stopped. That single number tells us whether Path 2 alone covers a week of shorts, or whether Path 3 is mandatory.

If we ever need volume beyond what pooled accounts give, OpenAI's own Codex documentation points the way out: set an API key and the same image model bills at API rates instead — around $2.65 per 100 images on the discounted batch tier. Noting it only so we know the ceiling isn't a dead end. Not proposing it.

Risks — stated once, your call

The terms. OpenAI's Terms of Use forbid users to "automatically or programmatically extract data or Output" and to "circumvent any rate limits or restrictions." All three paths sit inside that language, Path 2 least visibly (it uses an official Codex feature through an unofficial wrapper), Path 1 most visibly (the extensions advertise randomised delays "to stay under rate limits").
What actually happens in practice. I found zero first-hand reports of a permanent ban for this. The observed penalty is temporary lockouts and repeated human-verification prompts. The real hazard is different: when OpenAI's classifiers do flag an account for anything, 2026's appeals have been auto-rejected. Small chance, but the downside is losing the account rather than getting a warning.
Chrome extensions specifically. Google's Web Store policy update takes effect 1 Aug 2026 and disallows extensions "designed to circumvent safety guardrails, usage restrictions, or other protective measures implemented by AI-powered services." Whether these two are covered isn't stated anywhere — but Path 1 may not survive the month. Another reason it's the test, not the destination.
Path 2's tool is small. Apache-2.0, proper tests and CI, but few users — no bug reports either way. Read it before running it, which I'll do as part of setting it up.
